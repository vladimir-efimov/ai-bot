## Практическое руководство от Yandex Cloud

Текстовое описание со ссылками на документацию Yandex Cloud можно найти в практическом руководстве - <a href=https://yandex.cloud/ru/docs/serverless-integrations/tutorials/telegram-ai-bot-workflows>Как создать бота в Telegram с поддержкой AI-агента с помощью Workflows</a>.

Замечания.

1. Для бота, который опрашивает пользователя и сам делает запрос к LLM, история сообщений не нужна. Создавать бакет не нужно.
2. В руководстве неправильно указаны права для сервисного акканута sa-workflows. Нужно добавить ai.assistants.editor.
3. Рабочий процесс в руководстве создается через YAWL-файл. На самом деле его проще создавать интерактивно, а потом, после создания, воркфлоу на всякий случай следует сохранить в виде YAWL-файла. Просто автору инструкции так было проще.

## Объединение Java-бота и Yandex Cloud:

По результатам выполнения действий в видео у нас должна получиться реализация первой схемы для Telegram бота. Осталось объединить рабочий процесс Yandex Cloud и Java-бота.

Согласно второй схеме, теперь Java-бот при рекомендации курса должен отправлять запрос в API-шлюз Yandex Cloud, а рабочий процесс Yandex Cloud отправит ответ непосредственно в Telegram-чат.

Патч _3_1_business_logic.patch_ адаптирует бизнес-логику для использования Yandex Cloud. В частности рекомендация курса осуществляется только на последнем шаге. Рекомендуется только один курс. Зато на промежуточных шагах дается возможность выбора направления.

Патч _3_2_yandex_cloud.patch_ реализует отправку запроса в Yandex Cloud. Запрос кроме краткой информации о курсе просит написать AI-агента пару вдохновляющих на обучения предложений.

## Дальнейшие шаги для продуктизации:

В курсе показана учебная версия бота, код не загроможен деталями, которые нужно было бы реализовать при разработке подобного бота для заказчика.
Конечно, список требований зависит от бюджета заказчика и специфики проекта. Но все же вот пара идей для продуктового решения:
  - ответы от AI-агента можно кэшировать, чтобы не тратить деньги при каждом запросе (в этом случае рабочий процесс отправляет ответ не в Telegram, а Java-боту, который должен стать веб-сервисом)
  - список курсов и возможность выбора направлений можно конфигурировать, чтобы заказчику не пришлось каждый раз обращаться к программисту при добавлении нового курса на платформу
